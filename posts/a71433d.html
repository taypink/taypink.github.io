批量自动化代打工具

使用 Ansible + Jinja2 批量下发配置的核心思想是“数据与逻辑解耦”：

  • Jinja2 模板只存放通用的 CLI 配置语法逻辑（包含循环与判断）
  • YAML 变量文件只存放具体的业务数据（每台交换机的特定 VLAN 编号、接口名称、对端描述）。
  • Playbook 负责将两者拼合，并自动下发到对应交换机上保存
核心应用场景 具体工作内容 替代的传统做法
1. 批量配置下发 全网统一更新 NTP、SNMP、Syslog、AAA 认证、ACL 策略。 手工逐台 SSH 复制粘贴，容易漏敲、打错字符。
2. 定时巡检与配置备份 每天凌晨自动拉取所有核心/汇聚交换机的 running-config，归档并提交至 Git 仓库。 手工导出配置或依赖昂贵、笨重的第三方闭源网管软件。
3. 变更前后的比对 (Pre/Post Check) 割接前后批量采集接口状态（show ip int brief）、路由表（show ip route），自动导出为文件比对差异。 截屏或人工核对数十台设备的终端回显。
4. 配置模板化生成 用 Jinja2 模板 + Excel/YAML 数据表，一键渲染出 100 台机柜接入交换机的完整初始化配置。 复制模板文档，狂按 Ctrl+F 替换 VLAN 号和管理 IP。

阶段：

第一阶段：先当批量脚本用

  • 不用一上来就学复杂架构，先用 cisco.ios.ios_command 批量跑 show run、show ip interface brief 做日常配置备份和健康巡检。

第二阶段：模板化下发（Jinja2）

  • 将端口配置、BGP 对等体配置抽象成 Jinja2 模板，把 IP、AS 号等变量抽离到 YAML 文件中，实现“数据与配置分离”。

第三阶段：结合 Git 与 CI/CD 流程

  • 把网络配置文件托管在 GitLab/GitHub 上，利用 Git 的审查（Merge Request）与版本追溯机制，配合 Ansible 自动化执行网络割接。

Windows WSL2 + VS Code

在 Windows 上学习自动化，VMware 虚拟机的体验其实不如 WSL2（Windows 系统的 Linux 子系统）：

  • 资源占用极低：不需要为 VMware 划分固定内存和 CPU，随开随用。
  • 原生开发体验：Windows 端安装 VS Code，配合 Remote - WSL 插件，可以直接在 VS Code 里编写 YAML/Jinja2 模板，下方终端直接就是真实的 Linux 环境，编写与调试非常流畅。
