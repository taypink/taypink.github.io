MD-102

Entra ID

Autopilot：新电脑开箱连上 Wi-Fi 自动配置公司策略和软件。

Entra ID Join：设备直接上云；Hybrid Join：本地 AD + 云端双重加入。

Configuration Profile vs. Compliance Policy：前者是“给电脑下发设置”（如强制开 BitLocker），后者是“检查电脑合不合格”（没开 BitLocker 就标记为不合规）。

Conditional Access：门禁系统（只有“合规”的设备才能访问公司邮箱和 Teams）。

App Protection (MAM)：仅管控 Outlook/OneDrive 里的公司数据，不控制员工私人手机系统。

Entra ID 是通行证：验证用户身份并确认设备归属。

Intune 是云管家：替代传统的 GPO，在云端远程管理设备、下发策略和推送软件。

Autopilot 是自动化管道：新电脑出厂开机后，把设备无缝接入 Entra ID 和 Intune 的自动化流程。

第 1 步：搞定 Entra ID（设备接入类型）

  • 学习目标：分清设备以什么身份连入微软云端。
  • 核心考点：
    • Entra Registered：员工个人设备（BYOD），仅做轻量应用管控。
    • Entra Joined：公司所有的全新云原生电脑，完全由云端管控。
    • Microsoft Entra Hybrid Joined：既加入了本地传统 AD，又同步到了云端 Entra ID。
    • MDM 自动注册范围：在 Entra ID 中开启自动注册（None / Some / All）。

第 2 步：搞定 Windows Autopilot（设备开箱即用）

  • 学习目标：理解无需 IT 工程师在场、用户开机即用的原理。
  • 核心考点：
    • 硬件 Hash（Hardware Hash）：如何通过 PowerShell 导出并上传到 Intune。
    • Autopilot 配置文件：设置用户驱动模式（User-Driven）与自部署模式（Self-Deploying）。
    • 注册状态页（ESP）：用户登录桌面之前，强制等待关键安全软件安装完毕。

第 3 步：搞定 Intune 策略配置与安全（替代 GPO）

  • 学习目标：掌握如何批量给电脑下发合规要求和系统设置。
  • 核心考点：
    • Settings Catalog：现代策略配置库，几乎涵盖了所有 Windows 核心配置项。
    • Group Policy Analytics：将现有的本地 GPO 导出为 XML，上传到 Intune 分析哪些能直接转为云策略。
    • 合规性策略 (Compliance Policy) + 条件访问 (Conditional Access)：组合拳机制（例如：若设备未开启 BitLocker 加密，则标记为“不合规”，条件访问策略随即拦截其访问公司邮件）。

第 4 步：搞定应用部署与系统更新

  • 学习目标：掌握日常运维中的应用安装与补丁管控。
  • 核心考点：
    • Win32 应用打包：使用官方工具 IntuneWinAppUtil.exe 将 .exe / .msi 封装为 .intunewin。
    • 检测规则（Detection Rules）：配置注册表路径、文件路径或 PowerShell 脚本让 Intune 判定软件是否已成功安装。
    • Windows Update Rings（更新圈）：配置质保补丁与功能更新的推迟天数、维护时间窗口。
